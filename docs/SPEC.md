# 금융 MBTI 기능 명세

## 1. 서비스 범위

금융 MBTI는 사용자가 8개의 객관식 질문에 답하고, 네 개의 금융 성향 축을 계산해 결과를 확인하는 서비스다.

- 프론트엔드: `frontend/`의 Next.js
- 백엔드: `backend/`의 FastAPI
- 데이터베이스: `backend/supabase/`에서 관리하는 Supabase PostgreSQL
- 프론트엔드는 FastAPI API를 통해 질문과 결과 데이터를 사용한다.

## 2. 질문 구성

총 8문항이며, 각 축마다 2문항을 제공한다.

| 축 | 성향 |
|---|---|
| P / A | 직간접 투자형 |
| N / S | 정보 분석형 |
| F / D | 자산 배분형 |
| T / H | 투자 호흡 |

각 질문은 4지 선다형이다. 선택지는 첫 번째 성향에서 두 번째 성향까지 다음 점수를 가진다.

- 강한 첫 번째 성향: `-2`
- 약한 첫 번째 성향: `-1`
- 약한 두 번째 성향: `+1`
- 강한 두 번째 성향: `+2`

## 3. 결과 계산

1. 같은 축에 속한 두 문항의 점수를 합산한다.
2. 합계가 0보다 작으면 첫 번째 성향을 선택한다.
3. 합계가 0보다 크면 두 번째 성향을 선택한다.
4. 합계가 0이면 기본 성향을 적용한다.

기본 성향은 다음과 같다.

| 축 | 기본 성향 |
|---|---|
| P / A | P |
| N / S | N |
| F / D | D |
| T / H | H |

각 축의 첫 번째 성향 비율은 `50 - (합계 × 12.5)`로 계산하고 `0~100` 범위로 제한한다. 두 번째 성향 비율은 `100 - 첫 번째 성향 비율`이다. 최종 결과 코드는 `P/A → N/S → F/D → T/H` 순서의 네 글자로 구성한다.

## 4. 사용자 흐름

1. 시작 화면에서 테스트를 시작한다.
2. FastAPI에서 질문 목록을 불러온다.
3. 한 화면에 질문 하나와 4개 선택지를 표시한다.
4. 선택 전에는 `다음` 버튼을 비활성화한다.
5. `이전`으로 돌아가도 기존 답변을 유지하고 변경할 수 있다.
6. 마지막 문항에서는 `다음`을 `결과 보기`로 표시한다.
7. 모든 답변을 FastAPI에 제출한다.
8. 백엔드가 답변을 검증하고 계산한 결과를 저장 또는 반환한다.
9. 결과 유형, 네 축의 비율, 유형 설명, 캐릭터 이미지를 표시한다.
10. 결과 코드 URL을 복사하거나 공유할 수 있다.

## 5. API 기능

초기 API 경로는 `/api/v1`을 사용한다.

| 기능 | 메서드 | 경로 |
|---|---|---|
| 질문 조회 | GET | `/api/v1/questions` |
| 테스트 제출 및 결과 계산 | POST | `/api/v1/assessments` |
| 결과 조회 | GET | `/api/v1/results/{code}` |
| 서버 상태 확인 | GET | `/health` |

실제 요청·응답 필드와 인증 여부는 구현 전에 확정한다. FastAPI가 OpenAPI 문서를 제공하며, 프론트엔드는 정의된 API 계약만 사용한다.

## 6. 데이터 구조

### Question

```json
{
  "id": "ns-01",
  "axis": "NS",
  "prompt": "질문 내용",
  "choices": [
    { "id": "a", "label": "선택지", "score": -2 },
    { "id": "b", "label": "선택지", "score": -1 },
    { "id": "c", "label": "선택지", "score": 1 },
    { "id": "d", "label": "선택지", "score": 2 }
  ]
}
```

### Assessment submission

```json
{
  "answers": [
    { "question_id": "ns-01", "choice_id": "a" }
  ]
}
```

### Result

```json
{
  "code": "PNDH",
  "name": "결과 유형명",
  "summary": "결과 설명",
  "percentages": {
    "P": 62.5,
    "A": 37.5
  },
  "image_url": "/images/results/pndh.webp"
}
```

## 7. 예외 처리

- 질문 목록 조회 실패: 재시도 또는 오류 안내를 표시한다.
- 질문·선택지 데이터가 없거나 불완전함: 테스트를 시작하지 않고 오류를 표시한다.
- 답변 누락, 중복 답변, 존재하지 않는 질문·선택지 ID: FastAPI가 `4xx`로 응답한다.
- 결과 코드가 유효하지 않음: `404` 결과 화면을 표시한다.
- DB 오류와 예상하지 못한 서버 오류: 상세 내부 정보를 노출하지 않고 `5xx`로 처리한다.
- 개인정보와 비밀키는 응답이나 로그에 포함하지 않는다.

## 8. 제외 범위

- 질문의 복수 선택
- 프론트엔드의 Supabase 직접 접근
- 관리자 페이지와 CMS
- 소셜 로그인 및 사용자 인증(별도 결정 전까지)
- 결과 외 개인 금융정보 저장

## 9. 완료 조건

- 사용자가 8개 질문에 각각 하나의 답변을 선택할 수 있다.
- 선택하지 않은 문항에서는 다음 단계로 이동할 수 없다.
- 이전 단계로 이동해도 답변이 유지되고 변경할 수 있다.
- 모든 답변 제출 시 네 축의 점수와 결과 코드가 계산된다.
- 동점 축은 정의된 기본 성향으로 판정된다.
- 백엔드가 잘못된 입력을 거부한다.
- 결과 URL로 결과를 다시 조회할 수 있다.
- 프론트엔드와 백엔드 테스트 및 빌드 검증이 통과한다.
